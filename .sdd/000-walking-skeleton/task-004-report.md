## 2. Quyết định kỹ thuật đáng chú ý

- **Identity**: dùng `generatedByDefaultAsIdentity()` (GENERATED BY DEFAULT AS IDENTITY) cho
  mọi PK `bigint`, không phải `generatedAlwaysAsIdentity()`. Data-model chỉ nói "bigint
  identity", không chỉ định ALWAYS/BY DEFAULT. Chọn BY DEFAULT vì T005 (seed) hoặc test
  fixtures nhiều khả năng cần chèn id tường minh mà không phải viết `OVERRIDING SYSTEM VALUE`.
  Nếu T005 cần ALWAYS thay vì vậy, đây là điểm cần một migration sửa, không phải sửa tay DB.
- **Mode số**: mọi cột `bigint` (id, `category_id`, `product_id`, `price`, `order_id`,
  `actor_account_id`) dùng `{ mode: 'number' }` (map sang kiểu JS `number`, Drizzle
  `PgBigInt53`), không dùng `mode: 'bigint'` (JS `BigInt`). Phù hợp cho một walking skeleton —
  giá trị VND và id sẽ không chạm ngưỡng an toàn của `number`. Nếu một task sau cần `BigInt`
  thật (ví dụ hiển thị số cực lớn), đổi mode là việc của task đó, không phải task này.
- **Timestamptz**: dùng `timestamp(col, { withTimezone: true, mode: 'string' })` — cột SQL là
  `timestamp with time zone`, giá trị JS là chuỗi ISO (không parse thành `Date`), tránh mất
  timezone offset khi round-trip qua driver `pg`.
- **Check constraint name**: đặt tên tường minh (`product_price_non_negative`,
  `stock_quantity_non_negative`, `stock_ledger_delta_non_zero`,
  `stock_ledger_quantity_after_non_negative`) thay vì để Drizzle tự đặt tên ẩn danh — dễ đọc
  trong thông báo lỗi (xem mục 3) và dễ tham chiếu ở migration sau.
- Đường dẫn `schema`/`out` trong `drizzle.config.ts` là tương đối so với **cwd lúc chạy lệnh**
  (không phải so với thư mục chứa file config) — đã xác nhận trong mã nguồn
  `drizzle-kit/bin.cjs` (`path.resolve(process.cwd(), ...)`). Script `db:migrate` chạy từ gốc
  repo nên `./db/schema/index.ts` và `./db/migrations` trỏ đúng.

### Chứng minh `CHECK (quantity >= 0)` chặn thật
Chuẩn bị: `INSERT INTO product (...) VALUES (...) RETURNING id;` → `id=1`;
`INSERT INTO stock (product_id, quantity, updated_at) VALUES (1, 10, now());`

```
$ psql ... -c "UPDATE stock SET quantity = -1 WHERE product_id = 1;"
ERROR:  new row for relation "stock" violates check constraint "stock_quantity_non_negative"
DETAIL:  Failing row contains (1, -1, 2026-09-19 14:48:47.304696+00).
```

### Chứng minh `RESTRICT` chặn thật
Chuẩn bị: `INSERT INTO stock_ledger (product_id, delta, quantity_after, reason) VALUES (1, 10, 10, 'manual_adjustment');`

```
$ psql ... -c "DELETE FROM product WHERE id = 1;"
ERROR:  update or delete on table "product" violates RESTRICT setting of foreign key constraint "stock_ledger_product_id_product_id_fk" on table "stock_ledger"
DETAIL:  Key (id)=(1) is referenced from table "stock_ledger".
```

Sau khi chứng minh, đã `TRUNCATE stock_ledger, stock, product_image, product, category
RESTART IDENTITY CASCADE;` để trả database về trạng thái trống cho task sau.
